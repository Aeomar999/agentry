# Decisions

These are the decisions behind how Agentry is built and why, oldest first. Each one is dated, and the user's own words are quoted as they were written.

- 2026-10-15 Proofs first, then the main build. Proof code is never imported; findings are rewritten properly. Rules out copying proof packages wholesale.
- 2026-10-15 Go for the server, worker and hook, as one `agentry` binary; TypeScript and React for the web board, embedded in the binary. Rules out a separate runtime on worker machines.
- 2026-10-15 SQLite through the pure-Go driver for v1, append-only by triggers, one writer. Postgres or NATS only when there are many workers.
- 2026-10-15 Engines run in never-ask mode; Agentry's hook is the only gate. Requires the hook's own deadline, because a killed hook fails open in that mode.
- 2026-10-15 Prompts are delivered as one typed line pointing at a file in the worktree, never pasted. Proof 02: pastes get wrapped, `send-keys` stops at 16 KB, and a leading `!` runs as a shell command past the gate.
- 2026-10-15 Developers approve their own agents' requests in v1; every request is routed to an approver so senior approval can be added later without changing the gate.
- 2026-10-15 One repository, `agentry`: the binary in `cmd/agentry`, Go packages in `internal/`, the board in `web/`, proofs kept outside the repository. Confirmed by the user. Replaces the `agentry-api` / `agentry-web` / `agentry-cli` split in the original idea notes, because v1 is one binary.
- 2026-10-15 Git on branch `dev` (the house rule names branches after environments). One commit per task, including the plan file of the time. Confirmed by the user.
- 2026-10-15 Remote: a private GitLab project, `dev` pushed after each task. The user asked for the GitLab repo; private because nothing says it should be public yet. The module path matches it.
- 2026-10-15 `.gitignore` already covered `bin/`; the first build task needed no change to it.
- 2026-10-16 The goal moved from the full core loop to the coordinator MVP, at the user's request. The old list of next tasks is kept: what the MVP needs stays next, the rest is put off until later.
- 2026-10-16 A task, not a ticket, in the MVP's code and page: it is the user's word. Event names follow (`task.created`); the board can rename later if it needs tickets.
- 2026-10-16 Agents are data in the event log (`agent.created`, `agent.changed`), not files or code. The five defaults ship in the binary only as the seed for first start. Rules out a hard-coded list of roles: the user wants to add and edit agents from the page, and the coordinator must route to whatever agents exist.
- 2026-10-16 The coordinator is an ordinary agent with its own prompt, like the others ("supervisor is just an agent"). It answers in a fixed format that the loop parses; it never starts agents itself. The loop adds the current agent list to its prompt each turn.
- 2026-10-16 Each agent turn is a fresh Claude session in the task's worktree, started with its prompt plus the coordinator's instructions on the command line. Its final message (the `Stop` hook's `last_assistant_message`, proof 03) is its report. Rules out typing follow-ups into a running session for the MVP.
- 2026-10-16 Safety stops: 24 turns since the task started or the user last answered (about 12 handoffs there and back), or 3 issues in a row, and the task goes to the user. Without them a coordinator that keeps sending work back, or an agent that keeps failing to start, loops forever. Counted in turns rather than handoffs because coordinator turns that only raise issues cost the same.
- 2026-10-16 The deployer merges the task branch into `dev` and pushes, and the push always asks. Chosen by the user over running a deploy command or preparing only.
- 2026-10-16 Each task names a local repo path on the page; `serve --repo` sets the default. Chosen by the user over a sample repo or this one.
- 2026-10-16 The MVP page is one plain HTML file with a little script, embedded in the binary. React waits for the full board. Rules out a build step for the MVP.
- 2026-10-16 The admin UI is React with Vite, not Next.js: Agentry is one Go binary on this machine, and the Go server already does the server's work (API, websocket terminal, token). Vite builds static files that the binary embeds, so `agentry serve` stays one process; Node is needed only to change the UI. The built files are committed, so `go build` and `go install` work without Node. Chosen by the user.
- 2026-10-16 The UI is clean and sharp, at the user's request: no shadows ("i don't like the shadows please"), no rounded accent stripes on the active item ("make it look more AI"), a 1px focus line ("just a small one sleeky should work"), nearly square corners. Selection is a flat lighter surface. These override the gitlab-admin-ui skill where they differ.
- 2026-10-16 The desk is Claude Code run by Agentry, not a chat box written for the page, so it reads the repo with Claude's own tools and you talk to it as you would anywhere: "a claude entry point that I can actually interact at and everthing I say there gets prepared well to fit the system and sent as a prompt to the ochestrator". It never gets the UI token: its own token opens creating, reading and answering tasks, because a model must not approve an agent's actions.
- 2026-10-16 The coordinator names tasks, at the user's request: "let user set the title but let the cordinator read the task and when it konw what it is about it should rename the title". The rename rides on any decision (`"title"`), so it costs no extra turn; the new-task page drops the repository field ("I don't even think repository should be mentioned").
- 2026-10-16 The desk resumes only its own conversation, by the session id it started with, never `--continue`: that picks the newest conversation in the folder, which can be someone else's Claude session.
- 2026-10-16 An agent's workers are a list of machines, and none means the machine Agentry runs on, at the user's request: "there can be a case of we don't have any worker, and it is just the system and it should work too". Until other machines can be added there are none, so a named worker is refused rather than kept and ignored.
- 2026-10-16 Moving a card on the board is an instruction to the coordinator, not a move: the board shows where the log says a task is, and the coordinator decides.
- 2026-10-16 The board's columns are stages (Backlog, To do, In progress, Review, Done), not one per agent, at the user's request: "I think it should be generic columns and agents can jump in when they want to". An agent's `column` places its work; parking in To do or the Backlog is the one state you set yourself.
- 2026-10-16 A budget counts every token the model read and wrote, cache reads included: that is what the transcript says was used, and leaving cache reads out would make a turn look ten times cheaper than it was. The task is checked between turns, not stopped mid-turn: an agent cut off halfway leaves work half done.
- 2026-10-16 A question's page runs in a sandbox with no network and its own origin, and what it sends is a draft you send yourself: the page is written by a model, so it may show and suggest, never act or read anything of yours.
- 2026-10-16 An agent's knowledge travels through a file in the worktree, read back when the turn ends, so agents edit it with the tools they already have and no new token or command; a change is recorded as the agent, and an agent can change only its own.
- 2026-10-16 Agentry deploys as one container on Berth (`agentry dev server`, branch `dev`), pinned to one node at the user's request. Its home is one volume: Claude's sign-in, the repos and Agentry's data, so a deploy keeps them and Berth's nightly stop-and-copy backs them up. Claude Code is pinned in the image, outside the volume, so the image decides the version.
- 2026-10-16 A terminal session has one size, and any viewer may set it while nobody else is in control. Rules out letting each viewer see its own size, which tmux can't do for one pane.
- 2026-10-16 Every proof finding the MVP needs is listed with the task that uses it (now [the proofs table](design/proofs.md), with where each is used), at the user's request ("the feaures that we have built in the proofs, make sure to use them please to make things workk well"). This brought the terminal panel, the Codex adapter and the prompt hash check back into the MVP. Proof code is still ported, not imported.
- 2026-10-16 One concern per package, at the user's request: `internal/events`, `store`, `tasks`, `agents`, `coordinator`, `engines`, `hook`, `worktrees`, `sessions`, `policy`, `watchdog`, `web`. Packages depend downward only (`events` depends on nothing). Each file does one job, and names say what it does without a comment.
- 2026-10-16 Adapters return engine-neutral signals, not catalogue events, so `engines` depends on nothing; package hooks turns signals into proposals. The proof's adapter returned events, which tied every adapter to the catalogue.
- 2026-10-16 Agentry never writes Claude's trust into `~/.claude.json`: it is the user's file, and Claude rewrites it while running. An untrusted repo shows the dialog in the session instead; the watchdog flags a prompt that never arrives as waiting for you, and you answer it from the terminal panel.
- 2026-10-16 A turn waiting on something only a person can answer (a prompt never acknowledged, or the engine's own permission prompt) is Needs you, besides `action.asked`. Proof 05's flicker came from the transient permission notification; this lasts until the agent acts or the prompt arrives.
- 2026-10-16 The policy is a TOML file, not code, at the user's request ("I don't want rules in code please"; "let use toml please"). TOML because a hand-edited safety file must not guess types (YAML), must allow comments (JSON) and must keep patterns readable (single-quoted literal strings). Rules match with words and globs over a parsed shell command (mvdan.cc/sh), not regexes; every rule carries a `why` field, which survives the page rewriting the file where comments wouldn't. One protection stays in code: agents can never touch the policy file or Agentry's data, or an agent could delete that rule and allow itself anything.
- 2026-10-16 The shipped policy allows everything (`use_for_everyone = "allow-everything"` in `default.toml`), at the user's request. The profiles stay in the file and are one commented-out line away; Agentry's own files stay protected either way.
- 2026-10-17 Released publicly, at the user's request: the repo is public on GitHub (the `github` remote), and `dev` is pushed to both GitLab and GitHub. This replaces the 2026-10-15 private-project decision.
- 2026-10-17 Downloads are published as GitHub releases, at the user's request (tag vX.Y.Z on dev, zips from make package); GitLab keeps only the check/build/deploy pipeline.
